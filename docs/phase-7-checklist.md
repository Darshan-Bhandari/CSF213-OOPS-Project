# Example application workflows

These examples use the seeded demo accounts described in the [macOS and Linux](../MAC_START_HERE.md) and [Windows](windows-demo.md) setup guides. Use fictional incident descriptions for evaluation.

## 1. Reporting and assignment

Report a Campus Wi-Fi / Network incident as a Campus Community member. Set impact and urgency to 2. Confirm score 12 (P2) and review the response and resolution deadlines. If an eligible technician is available, inspect their queue, notification and the administrator’s audit view.

## 2. Investigation and closure

As the assignee, acknowledge the incident and start investigation. Add an internal note and request information. As the reporter, reply to the request and confirm that the internal note is hidden. Resolve the incident, reject the first resolution as the reporter, and confirm that the previous resolution remains in history. The assigned technician acknowledges the new cycle, starts investigation and submits a second resolution. The reporter can verify, close and rate the incident.

## 3. Duplicate incident correlation

Use the [four-report example](incident-correlation.md). As an administrator, link three related reports to one master. Confirm the links and audit entries and inspect each report’s independent status and SLA data.
